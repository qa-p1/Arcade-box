# Upstream and license review

Reviewed 2026-09-24. Versions below are upstream snapshots, not a substitute for versions and build options recorded in a release SBOM. Recheck on provider upgrades.

## Decisions

- Keep the desktop on supported Tauri 2; Tauri 3 is still pre-release. Use Svelte 5 with Vite.
- Use Wasmtime with the WebAssembly Component Model and WASI Preview 2 for public plugins. The Wasmtime 48 LTS line is a conservative deployment target and requires Rust 1.95. Do not base the SDK on WASI Preview 3 until upstream removes its experimental, unstable, incomplete status.
- Use rusqlite with bundled SQLite for reproducible local persistence. rusqlite and SQLite are permissively usable; SQLite itself is public domain.
- Treat media, image, OCR, archive, and PDF engines as separately versioned providers. Prefer compatible system installations. Bundle only pinned, audited builds: obligations depend on each provider artifact and enabled features/codecs.
- Keep Arcade-managed FFmpeg builds LGPL-only by default. Do not enable GPL or nonfree FFmpeg options without a release-level license decision. Record exact source, configure flags, and linked-library licenses.
- Use qpdf for structural PDF operations and optional JPEG recompression. The 12.4.x manual documents `--optimize-images` and `--jpeg-quality` (the latter added in 12.1); qpdf can recompress image streams but does not resample them. Treat any enabled JPEG recompression as lossy. qpdf does not render or extract text. Select rendering/text tools separately. MuPDF is AGPL-3.0 or commercial, so do not bundle without explicit review. PDFium is a possible BSD-style/Apache-2.0 candidate, but its Chromium-derived third-party set needs a separate audit.
- Use printpdf 0.12.8's MIT-licensed core writer for generated watermark overlays with the `images`, `jpeg`, and `png` features only. Keep `text_layout` disabled: its azul-layout dependency brings the MPL-2.0 azul-simplecss package into the normal graph, which requires extra license/source handling when distributed with GPL work. The configured core dependency graph excludes that package; verify again whenever printpdf features change. Text watermarks use built-in Helvetica and reject non-ASCII glyphs until an audited, user-selected font path is added.
- Prefer libarchive for archives. 7-Zip is a possible optional provider but has LGPL obligations and an unRAR restriction on some code; exclude restricted RAR code unless specifically reviewed.
- ZXing-C++ is Apache-2.0. Its current writer can include Zint, so inventory Zint and its notices when that writer path is enabled.
- Use age for interoperable encryption. Prefer a Rust minisign verifier after testing against upstream vectors. Decide on signing implementation only after defining key custody, rotation, and release policy.

## License posture

GPL-3.0-or-later is a reasonable candidate for the Arcade Box application, subject to a full dependency and distribution review before finalizing the project license. MIT, ISC, BSD, Apache-2.0, and public-domain components generally coexist with GPL-3.0-or-later when notices and terms are preserved. Apache-2.0 compatibility is with GPL version 3, not GPL version 2 only.

LGPL providers can be distributed alongside a GPL-3.0-or-later application when their terms are met. For a dynamically linked LGPL library, this commonly includes providing corresponding library source, allowing replacement/relinking, keeping notices, and documenting modifications. A separate process is a useful architecture boundary but is not, by itself, a legal conclusion about combined distribution. Treat each shipped provider package as a distinct compliance item.

Build features affect the result. FFmpeg can move from LGPL to GPL based on configure options and linked codecs; its nonfree option makes the resulting build non-redistributable under upstream's terms. PyInstaller yt-dlp executables are GPL-3.0-or-later because they contain GPL-licensed runtime code, while source and PyPI artifacts have different licensing composition. Do not label every artifact merely as “yt-dlp Unlicense.” Track notices, source/build provenance, and checksums for each artifact.

This is engineering guidance, not legal advice. Release builds must scan resolved Cargo, npm, native, and provider graphs, record exact artifacts and licenses, and ship required notices and source offers.

## Wayland global shortcuts

The Tauri v2 global-shortcut plugin depends on upstream global-hotkey. That crate documents Linux support as X11 only. The Tauri plugin also has an open upstream report that a shortcut registers but its callback does not fire on Wayland GNOME. It is not a Wayland implementation.

Use that plugin on Windows, macOS, and Linux X11. On Wayland, add a dedicated adapter over XDG Desktop Portal GlobalShortcuts using ashpd. Current ashpd 0.13.13 exposes this behind the global_shortcuts feature and requires Rust 1.87; this repository's Rust 1.95 MSRV accommodates it. The portal is intended for app-wide shortcuts and was introduced in xdg-desktop-portal 1.16. Desktop-specific backends provide portal interfaces, so probe the actual interface at runtime and show clear unsupported/conflict feedback. GNOME officially announced GlobalShortcuts support in February 2025; KDE and Hyprland also have upstream implementations. Do not infer portal availability just from a Wayland session.

The native Tauri plugin supports runtime registration, unregistration, and `is_registered` queries through `GlobalShortcutExt`. Its Rust `register`/`unregister` APIs return `Result`; the builder's shared handler receives events for shortcuts registered later through the extension API. `is_registered` reports the plugin's own registration map, not an operating-system query and not whether another process owns the same key. Use successful registration as the active status signal, preserve a controller-owned status snapshot for late-mounted UI, and surface registration errors. The error type distinguishes global-hotkey and Tauri errors, but its global-hotkey detail is a string rather than a portable conflict classification. For reconfiguration, attempt to register the candidate first so a conflict does not discard the working shortcut; then unregister the old binding and reconcile/report any partial failure.

## Windows provider process trees

On Windows, assigning the provider process to a Job Object and setting `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` lets cancellation or timeout terminate its descendants as well as the direct child. Start the process suspended, assign it before resuming its initial thread, and close/terminate the job before joining stdout readers so descendants cannot keep inherited pipe handles open. If job creation or assignment fails, fail the provider launch rather than running without process-tree containment. Microsoft documents nested Job Objects on Windows 8 and later; some managed/sandboxed host policies can still reject assignment, so report the containment error clearly.

## Release gates

1. Generate SPDX or CycloneDX SBOMs from exact release app, frontend, native, provider, model, and language-pack artifacts.
2. Preserve upstream LICENSE, NOTICE, copyright, and third-party files. Include corresponding source/build instructions for redistributed LGPL components as required.
3. Record provider URL, version, digest, signature result, build configuration, and enabled codecs/features.
4. Test actual Wayland activation. Distinguish portal absent, interface unsupported, user declined, shortcut conflict, and successful bind.
5. Re-audit when changing PDF rendering, FFmpeg flags, yt-dlp artifact kind, ZXing writer mode, or archive compression dependencies.
