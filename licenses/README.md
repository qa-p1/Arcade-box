# Third-party license audit

[`third-party.json`](third-party.json) records researched direct components and native provider candidates. [`resolved.json`](resolved.json), generated by `python3 scripts/license_inventory.py`, records the locked Cargo and npm dependency closure, including versions, declared license metadata, source, and checksums. Metadata alone is not a compatibility approval or a complete notice file. The release audit must check every artifact and its actual feature/build configuration.

The researched direct inventory may be provisional while component integration continues. Compare it with the resolved inventory whenever dependency manifests or lockfiles change. Review entries with missing license metadata manually and preserve the actual license and notice text from upstream distributions.

Before a release, resolve locked graphs for every supported target and feature set, verify each resolved package's SPDX metadata against its upstream license and notice, review provider/model assets separately, and update this inventory. Reject any incompatible dependency until a compatible version or distribution approach is documented. Release artifacts must include all required notices and a generated SBOM where practical.

## Current resolved snapshot

The resolved snapshot is generated from current Cargo/npm lockfiles and is expected to change as manifests, lockfiles, and features change. The inventory includes target-specific crates, but it does not establish which packages are actually linked into each release artifact. Expressions in the closure include MPL-2.0, Unicode-3.0, and several slash-separated declarations that require upstream text review. Review each package's actual feature and build graph; for example, printpdf's optional `text_layout` graph contains MPL-2.0 azul-simplecss, while Arcade Core currently disables that feature. This is an early audit checkpoint, not a release approval.
